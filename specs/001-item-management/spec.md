# フィーチャー仕様: Endfield 武器＆スキル早見アプリ — ミニマム仕様

**フィーチャーブランチ**: `001-item-management`\
**作成日**: 2026-04-15\
**更新日**: 2026-04-16\
**ステータス**: ドラフト\
**入力**: ユーザー説明: "Endfield 武器管理アプリ ミニマム仕様"

> **目的の補足**: このアプリの主目的は武器に付随するスキル情報を素早く確認（早見）することである。
> 武器一覧・詳細はスキル情報へのナビゲーション手段として機能する。
> **画像管理はコア機能ではなく補助機能**（武器の視覚的識別を助けるための付加機能）として位置づける。スキル表示が最優先であり、画像は未設定でもアプリの主目的は完結する。

## 明確化事項

### セッション 2026-04-15

- Q: 詳細画面における画像の配置位置 → A: 基本情報（武器名・レアリティ・カテゴリ・説明）とスキル一覧の**間**に、横幅を抑えた小さめのサイズで表示する。スキル一覧の視認性を妨げない補助的な配置とする
- Q: 一覧カードで `category` が省略された武器の表示 → A: カテゴリ欄に「-」（ハイフン）を表示する。DOM から除去せずレイアウトを統一する
- Q: `weapons.json` のデータ取得タイミング → A: React Router v7 の **`loader` 関数**で取得し `useLoaderData()` でコンポーネントに渡す。エラー時はルートの `errorElement` で処理する
- Q: レアリティの表示形式 → A: **「★5」形式**（★アイコン＋数値。例: rarity=5 → ★5）で表示する
- Q: レアリティフィルターの UI 形式 → A: `weapons.json` から動的生成する `<select>`。実際に存在するレアリティ値のみを昇順で選択肢に出す

## ユーザーシナリオとテスト _（必須）_

### ユーザーストーリー1 — 武器一覧を閲覧する（優先度: P1）

ユーザーはアプリを開くと、登録済みの武器が一覧表示される。
各武器には名前・レアリティ・カテゴリ・画像（未設定時はプレースホルダー）が表示され、
目的の武器（＝スキルを確認したい武器）をすばやく見つけられる。

**この優先度の理由**: スキル早見の入口となる機能。一覧から武器を選んでスキルを確認するフローの第一歩であり、すべての機能の土台となる。

**独立テスト**: `weapons.json` に武器が1件以上存在する状態でアプリを開くことで完全にテスト可能であり、
武器が画像の有無に関わらず一覧に表示されるという価値を提供する。

**受け入れシナリオ**:

1. **前提** `weapons.json` に複数武器が登録されている、**操作** アプリを開く、**期待** 全武器が一覧に表示される
2. **前提** 一部武器に画像が未設定、**操作** 一覧を表示する、**期待** 未設定武器はプレースホルダーが表示され、UIが崩れない
3. **前提** 武器が0件、**操作** 一覧を表示する、**期待** 空状態を示すメッセージが表示される

---

### ユーザーストーリー2 — 武器のスキルをすばやく確認する（優先度: P1）

ユーザーは一覧から武器を選択すると、その武器の詳細情報とともに、
武器が持つスキル（スキル名・効果説明）をすべて確認できる。
これが本アプリのコア機能であり、「スキル早見」の実態となる。

> **v1 スコープ**: スキルの表示項目は **スキル名と効果説明のみ** とする。レベル情報・強化値などは将来拡張とし、v1 では扱わない。

**この優先度の理由**: アプリの主目的がスキルの早見であるため、スキル情報の表示は最優先要件。
一覧と組み合わせることで「探してスキルを確認する」というコアユースケースが完結する。

**独立テスト**: 一覧から武器をクリックすることで詳細画面に遷移し、スキル一覧が表示されることをテスト可能。

**受け入れシナリオ**:

1. **前提** 一覧が表示されている、**操作** 武器をクリック、**期待** 詳細画面に遷移し、武器情報とスキル一覧が表示される
2. **前提** 詳細画面を表示している、**操作** スキルセクションを確認、**期待** スキル名・効果説明が読み取れる状態で表示される
3. **前提** 詳細画面を表示している、**操作** 画像が未設定の武器を選択、**期待** プレースホルダーが表示され、スキル情報は正常表示される

---

### ユーザーストーリー3 — ローカル画像を武器に設定する（優先度: P2）

ユーザーは詳細画面から自分の端末上の画像ファイルを選択し、その武器に紐づけて保存できる。
設定後は画像が即時反映され、次回アクセス時も保持されている。

**この優先度の理由**: 画像設定は**補助機能**であり、スキル早見というコア機能は画像なしで完結する。
武器の視覚的な識別を助けるための付加機能として位置づける。スキル表示（P1）が完成していることを前提として取り組む。

**独立テスト**: 詳細画面でファイル選択→保存→再表示のフローでテスト可能。
画像がローカルにのみ保存され、サーバー送信が発生しないことを確認できる。

**受け入れシナリオ**:

1. **前提** 詳細画面を開いている（画像未設定）、**操作** 「画像を設定」ボタンを押してローカルファイルを選択、**期待** 画像が即時反映される
2. **前提** 画像を設定した武器の詳細画面、**操作** ページを再読み込みする、**期待** 設定した画像が引き続き表示される
3. **前提** 画像が設定済み、**操作** 「画像を削除」ボタンを押す、**期待** プレースホルダーに戻る
4. **前提** 画像設定操作、**操作** ネットワーク通信を監視する、**期待** 画像データのサーバー送信が発生しない

---

### ユーザーストーリー4 — 武器を名前・カテゴリ・レアリティで絞り込む（優先度: P3）

ユーザーは一覧画面で名前検索・カテゴリフィルター・レアリティフィルターを使って武器を絞り込める。

**この優先度の理由**: 一覧・詳細・画像設定の機能が完成した後の利便性向上機能。
武器数が少ない段階では必須ではない。

**独立テスト**: 検索ボックスやフィルターを操作し、表示される武器が絞り込まれることをテスト可能。

**受け入れシナリオ**:

1. **前提** 一覧が表示されている、**操作** 検索ボックスに武器名の一部を入力、**期待** 入力文字列に一致する武器のみ表示される
2. **前提** 一覧が表示されている、**操作** カテゴリを選択してフィルター、**期待** 該当カテゴリの武器のみ表示される
3. **前提** フィルターを適用中、**操作** フィルターをクリア、**期待** 全武器が再表示される

---

### エッジケース

- `weapons.json` が不正なJSON形式の場合、アプリが起動できない可能性がある
- 武器にスキルが1件も紐づいていない場合、スキルセクションが空になる（「スキルなし」などの表示が必要）
- スキルの効果説明が非常に長い場合、詳細画面のレイアウトが崩れる可能性がある
- 存在しない武器IDでURL直接アクセスした場合、Not Found 画面を表示しなければならない
- IndexedDB が利用不可の環境では画像機能全体が無効化され、スキル閲覧は正常に動作し続けなければならない
- 画像設定時に5MBを超えるファイルや非対応フォーマットを選択した場合、エラーメッセージを表示してスキル閲覧には影響を与えないこと
- 画像の再設定時に旧画像がストレージに残存し続けることによるストレージ枯渇

## 要件 _（必須）_

### 機能要件

- **FR-001**: システムはカテゴリ別静的 JSON ファイル（`public/weapons/{category}.json`）とエフェクトファイル（`public/effects/*.json`）から武器一覧をロードして画面に表示しなければならない（MUST）
- **FR-001a**: 武器データはカテゴリごとに `public/weapons/sword.json`・`greatsword.json`・`handcannon.json`・`polearm.json`・`arts-unit.json` の5ファイルに分割して配置する静的ファイルとし、外部APIや自動取得は行わない（MUST）
- **FR-001b**: スキルデータは `public/effects/base-effects.json`・`additional-effects.json`・`skill-effects.json` の3ファイルに定義し、ロード時に武器の `effectRefs` を解決して `skills` として付与する（MUST）
- **FR-002**: システムは各武器の uid・名前・レアリティ・カテゴリ・画像（またはプレースホルダー）を一覧に表示しなければならない（MUST）
- **FR-002a**: カテゴリはロード時に必ず付与されるため、常に表示する（MUST）
- **FR-002b**: レアリティは「★N」形式（★アイコン＋数値。例: rarity=5 → ★5）で表示する。一覧・詳細画面で共通の形式とする（MUST）
- **FR-003**: ユーザーは一覧から武器を選択して詳細画面に遷移できなければならない（MUST）
- **FR-003a**: URL ルーティングは `/weapons`（一覧）と `/weapons/:weaponId`（詳細）の2画面構成とする。`:weaponId` は `Weapon.uid`（例: `sword_1`）を使用する（MUST）
- **FR-003b**: 存在しない `weaponId` へのURLアクセスは Not Found 画面を表示しなければならない（MUST）
- **FR-003c**: 武器データのロードは React Router v7 の `loader` 関数で実行し、コンポーネントは `useLoaderData()` で取得する。エラー時はルートの `errorElement` で ErrorBoundary 画面を表示する（MUST）
- **FR-003d**: 詳細画面での武器検索は `Weapon.uid` を使って一致判定する（MUST）
- **FR-004**: 詳細画面は武器ID・名前・レアリティ・カテゴリ・説明・画像（またはプレースホルダー）を表示しなければならない（MUST）
- **FR-004a**: 詳細画面はその武器に紐づくスキルの一覧（**スキル名・効果説明のみ**、v1 ではレベル情報は表示しない）を表示しなければならない（MUST）
- **FR-004b**: スキルが存在しない場合は「スキルなし」などの適切な空状態を表示しなければならない（MUST）
- **FR-004c**: 詳細画面のレイアウトは以下の順序で縦に構成しなければならない（MUST）
  1. **上部**: 武器名・レアリティ・カテゴリ・説明などの基本情報
  2. **中間（補助）**: 画像（プレースホルダー含む）— 横幅を抑えた小さめサイズ。スキル一覧の邪魔にならない補助的な配置とする
  3. **主コンテンツ**: スキル一覧（本アプリのコア表示領域。視覚的に最も主張する）
- **FR-005**: ユーザーは詳細画面から端末上の画像ファイルを選択し、武器に紐づけて保存できなければならない（MUST）
- **FR-005a**: 対応する画像フォーマットは PNG・JPEG・WebP のみとし、それ以外はエラーメッセージを表示して処理を中止する（MUST）
- **FR-005b**: 画像ファイルの最大サイズは 5MB とし、超過した場合はエラーメッセージを表示して処理を中止する（MUST）
- **FR-005c**: 画像の再設定時は旧画像を IndexedDB から削除してから新画像を保存する（MUST）
- **FR-005d**: IndexedDB が利用不可の環境では画像機能を無効化し、スキル閲覧は通常通り動作しなければならない（MUST）
- **FR-005e**: 画像保存失敗時はエラーメッセージを表示し、スキル閲覧には影響を与えてはならない（MUST）
- **FR-006**: 保存した画像はページ再読み込み後も表示され続けなければならない（MUST）
- **FR-007**: ユーザーは武器に設定した画像を削除できなければならない（MUST）
- **FR-008**: 画像データはいかなる状況においてもサーバーに送信してはならない（MUST NOT）
- **FR-009**: 画像未設定の武器はプレースホルダーを表示し、UIが崩れてはならない（MUST）
- **FR-010**: ユーザーは武器名で一覧を検索できなければならない（SHOULD）
- **FR-010a**: 武器名検索は部分一致とし、大文字・小文字を区別しない（SHOULD）
- **FR-011**: ユーザーはカテゴリ・レアリティで一覧を絞り込めなければならない（SHOULD）
- **FR-011a**: 名前検索・カテゴリフィルター・レアリティフィルターは AND 条件で適用する。未指定のフィルターは全件対象とする（SHOULD）
- **FR-011b**: カテゴリ・レアリティの各フィルター選択肢は `weapons.json` から動的に生成する。カテゴリは `undefined` を除いた一意の値を昇順で、レアリティは存在する値を昇順で列挙する（SHOULD）

### 空状態の表示方針

| 状態                        | 表示内容                                                                                                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| 武器データが0件             | 「武器データが見つかりません」                                                                            |
| 検索・フィルター結果が0件   | 「条件に一致する武器はありません」（名前検索が入力されている場合は「"{検索語}" を含む武器はありません」） |
| 画像未設定                  | 武器名の頭文字または共通プレースホルダーアイコンを表示                                                    |
| `weapons.json` 読み込み失敗 | 「データの読み込みに失敗しました。ページを再読み込みしてください」                                        |
| 画像保存失敗                | 「画像の保存に失敗しました。再度お試しください」                                                          |
| 非対応フォーマット選択      | 「PNG・JPEG・WebP 形式のファイルを選択してください」                                                      |
| ファイルサイズ超過          | 「ファイルサイズは 5MB 以下にしてください」                                                               |
| 不正な武器ID（URLアクセス） | Not Found 画面（武器が存在しない旨とトップへの導線）                                                      |

### キーエンティティ _（フィーチャーがデータを扱う場合に含める）_

- **Weapon（武器）**: カテゴリ別静的 JSON ファイル（`public/weapons/{category}.json`）に定義される管理対象。JSON 上の `RawWeapon` はスキル参照（`effectRefs`）のみを持ち、ロード時にカテゴリ・uid・解決済みスキル配列が付与されて `Weapon` となる。主要属性: `uid`（アプリ内一意識別子）、`id`（JSON上のID、形式: `{category}_{n}`）、`name`（表示名）、`rarity`（レアリティ数値）、`category`（分類、ロード時注入）、`description`（説明文、任意）、`skills`（解決済みスキル配列）
- **Skill（スキル）**: `public/effects/` 以下の3つのエフェクトファイル（`base-effects.json` / `additional-effects.json` / `skill-effects.json`）に定義される。武器 JSON は `effectRefs`（`{type, id}` 参照）を持ち、ロード時に解決されて `Weapon.skills` として付与される。v1 の表示対象属性: `name`（スキル名）、`description`（効果説明）のみ。1つの武器に複数スキルが存在する（配列）
- **UserWeaponImage（ユーザー画像）**: ユーザーが武器に紐づけたローカル画像。`weaponId`（= `Weapon.uid`）をキーとして端末ローカル（IndexedDB）に保存。主要属性: `weaponId`、`blob`（画像バイナリ）、`fileName`、`mimeType`、`updatedAt`

### データ型・値域の定義

| フィールド    | 型               | 値域・制約                                                                                                             |
| ------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `id`          | `string`         | 形式: `{category}_{n}`（例: `sword_1`）。空文字不可。同一カテゴリファイル内で一意                                      |
| `name`        | `string`         | 空文字不可                                                                                                             |
| `rarity`      | `number`         | 1以上の整数。小数・負数・0 は不正値                                                                                    |
| `description` | `string`         | 任意。省略時は `undefined`（詳細画面で非表示）                                                                         |
| `effectRefs`  | `array`          | **必須。スキル参照がない場合は `[]`（空配列）を設定する**。各要素は `{type, id}` 形式                                  |
| `category`    | `WeaponCategory` | JSON には書かない。ロード時にファイル名から注入。`"sword" \| "greatsword" \| "handcannon" \| "polearm" \| "arts-unit"` |
| `uid`         | `string`         | JSON には書かない。ロード時に `id` と同値で注入。ルーティング・画像キーとして使用                                      |

**データ読み込みエラーの区別**:

- いずれかのファイル（`/weapons/{category}.json` または `/effects/*.json`）が HTTP エラーまたは JSON パース失敗の場合は **全体エラー** として扱い、エラー画面を表示する
- JSON形式は正しいが一部エントリが不正（`rarity` が整数でない、`id` が空など）な場合は **当該エントリのみ除外** し、他の正常な武器は表示する
- `effectRefs` が参照するスキルIDがエフェクトファイルに存在しない場合は、そのスキル参照のみを無視して残りのスキルを表示する

### `weapons.json` 最小サンプル

```json
// public/weapons/sword.json
[
  {
    "id": "sword_1",
    "name": "サンプル武器",
    "rarity": 5,
    "description": "説明文（省略可）",
    "effectRefs": [
      { "type": "skill", "id": 1 },
      { "type": "base", "id": 2 }
    ]
  }
]

// public/effects/skill-effects.json
[
  {
    "id": 1,
    "type": "skill",
    "name": "スキル名",
    "description": "スキル効果説明"
  }
]
```

## v1 スコープ外（実装しないこと）

- 外部サイト・外部 API からの画像自動取得は行わない
- サーバーへの画像アップロードは行わない
- 武器データ（`weapons.json`）の自動更新・自動クロールは行わない
- 武器間のスキル比較機能は v1 では実装しない
- ログイン・ユーザー認証機能は実装しない
- 複数端末間での設定データの同期は行わない

## コンスティテューション制約チェック _（必須）_

> 参照: `.specify/memory/constitution.md` —
> このセクションはすべての仕様に含めること。

| 原則               | このフィーチャーへの影響                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I. クリーンコード  | `weaponId` などのキー名を定数化し、IndexedDB ストア名・操作関数の命名を意図が明確になるよう統一する。画像操作ロジックの重複を避ける                                               |
| II. 早期リターン   | 画像保存時の未選択チェック、IndexedDB 未対応ブラウザのガード、武器IDが存在しない場合の早期リターンを適用する                                                                      |
| III. テスト容易性  | IndexedDB アクセスはアダプター層に切り出し、ユニットテストはモック可能な形にする。`weapons.json` の読み込みロジック（スキルは内包済みのため別途解決不要）も純粋関数として分離する |
| IV. メソッドサイズ | 画像のBlobを受け取りIndexedDBへ保存する処理は30行を超える可能性がある。保存・取得・削除を別関数に分割して対処する                                                                 |
| V. SRP             | UI（一覧/詳細/スキルコンポーネント）・データ取得ロジック（`weapons.json` 読み込み）・スキルデータ取得ロジック・画像管理ロジック（IndexedDB操作）の責務を明確に分離する            |

## 成功基準 _（必須）_

### 測定可能な成果
